# ADR-0003: Автономия агента и границы безопасности

- Статус: accepted
- Дата: 2026-10-31

## Контекст

Агент должен автономно решать IT-задачи: читать и менять файлы, запускать
команды, работать с git. Пользователь выбрал режим без пошаговых
подтверждений. При этом агент работает на машине с приватной книгой и
пользовательскими файлами, поэтому «без подтверждений» не означает «без
границ».

## Решение

Агент автономен **внутри workspace** и не спрашивает подтверждение на каждое
действие. Границы задаются политикой, а не диалогом:

1. **Workspace confinement.** Все файловые операции резолвят путь
   (`Path.resolve()`) и обязаны оставаться внутри `BOOK_EXPERT_WORKSPACE`
   (по умолчанию — текущий проект). Симлинки, `..` и абсолютные пути вне
   workspace блокируются.
2. **Command policy.** Shell-команды выполняются внутри `bubblewrap`-песочницы:
   корень ФС read-only, workspace — writable, `/tmp` — private tmpfs, сеть
   выключена, если не включён `BOOK_EXPERT_ALLOW_REMOTE=1`. Дополнительно
   блокируются `sudo`, устройства (`dd`, `mkfs`), рекурсивное удаление корня,
   `shutdown/reboot`, shell-интерпретаторы, wrapper-команды (`env`, `timeout`,
   `xargs`, ...) и `find -exec`. Если `bwrap` не установлен, shell/git-инструменты
   отключены (fail-closed).
3. **Remote actions.** `git push/fetch/pull/clone/remote/submodule/ls-remote`,
   создание PR, деплой и любые действия, видимые другим, по умолчанию
   запрещены и включаются только явным `BOOK_EXPERT_ALLOW_REMOTE=1`. Это не
   пошаговое подтверждение, а осознанный opt-in на действия, меняющие общее
   состояние.
4. **Git safety.** Запрещены `git reset --hard`, `git clean -fdx`,
   `git push --force` на защищённых ветках и переписывание истории.
5. **Лимиты.** Максимум шагов агента, таймаут на команду, лимит размера
   файла/вывода. Таймаут агента — caller-side: `ThreadPoolExecutor` не умеет
   прерывать уже выполняющийся граф, поэтому поток может продолжить работу;
   side effects ограничены `agent_max_steps`, таймаутами инструментов,
   песочницей и audit. Для жёсткой остановки нужен отдельный процесс-раннер.
6. **Audit.** Каждый tool-call (RAG и coding) пишется в append-only JSONL
   (`data/artifacts/audit/`) с timestamp, tool, аргументами (redacted), кодом
   возврата и длительностью. Текст книги в audit не попадает.
7. **Kill switch.** `BOOK_EXPERT_AUTONOMY=off` оставляет только
   read-only RAG-инструменты.

## Последствия

- Агент не может «убежать» из проекта и не может незаметно изменить общую
  ветку/удалённый репозиторий.
- Опасные, но легитимные операции требуют изменения env или ручного действия
  пользователя — это осознанная цена.
- Prompt injection из текста книги не должен превращаться в tool-call:
  retrieved-контекст маркируется как данные, а инструменты с побочными
  эффектами не вызываются по инструкции из документа без явной цели
  пользователя.
- Политика тестируется негативными тестами (path traversal, timeout,
  запрещённая команда, remote без флага).
