# Калибровка LLM-судьи по независимой разметке (T86, 2026-11-04)

## Что проверялось

20 ответов «Агента» на `combined-120.local.json` (один отказ, поэтому 19
ответов дали утверждения), 152 утверждения (8 на ответ: 4 цитируемых и 4 без
цитат; при нехватке — добор из другой группы). Разметка —
**слепая, независимым агентом**: он видел только вопрос, утверждение и тексты
цитируемых фрагментов, без вердиктов судьи. Это не человеческая разметка;
ограничение зафиксировано ниже.

Судьи запускались на тех же ответах:

- `deepseek/binary` — 19 ответов с утверждениями, 152 утверждения;
- `ollama/qwen3.5:4b/binary` — 7 ответов, 56 утверждений;
- `deepseek/quote` — 3 ответа, 24 утверждения (quote-парсер покрывает не все
  утверждения, поэтому знаменатель меньше; остальные ответы дали `report.error`
  или неполный разбор).

## Результаты против независимой разметки

| Судья | n | accuracy | precision | recall | Cohen's kappa |
| --- | ---: | ---: | ---: | ---: | ---: |
| `deepseek/binary` (19 ответов) | 152 | **.8553** | .7614 | **.9853** | **.7153** |
| `ollama/binary` (7 ответов) | 56 | .8393 | **.7857** | .8800 | .6786 |
| `deepseek/quote` (3 ответа) | 24 | **.8750** | .8000 | .8889 | **.7391** |

Сырые вердикты и слепые метки лежат только в `/tmp/t86-*` и в репозиторий не
добавляются: в них есть фрагменты ответов и книг.

## Выводы

1. **Binary-судьи воспроизводят независимую разметку заметно лучше случайности**
   (kappa .68–.72). Это достаточная рабочая калибровка для сравнения прогонов,
   но не доказательство истины.
2. **DeepSeek склонен к ложноположительным вердиктам:** recall .985 при
   precision .761; 21 утверждение из 152 размечено как поддержанное, хотя
   разметчик счёл его неподдержанным. Локальная 4B сбалансированнее
   (P .786 / R .880), но на меньшем срезе.
3. **Quote-режим не лучше binary по kappa** (.739 против .715), но вывод
   опирается всего на 3 ответа/24 утверждения: quote-парсер часто не разбирает
   ответ целиком. Это сигнал, а не окончательный вердикт.
4. **Выбор судьи меняет вердикт:** сравнивать absolute precision/recall между
   прогонами с разными судьями нельзя. Для решений нужен фиксированный
   judge-профиль и, в идеале, человеческий golden set.
5. Ручная разметка остаётся открытым долгом: независимый агент — не человек,
   поэтому T86 закрывает воспроизводимость и калибровку, но не отменяет
   необходимость human-verified эталона.

## Воспроизведение

```bash
# пакет и context.json должны лежать в том же output-dir, где пойдут судьи
uv run python scripts/judge_calibration.py --limit 20 \
  --output-dir /tmp/t86-deepseek --packet-only
# разметчик заполняет /tmp/t86-deepseek/labels.json
uv run python scripts/judge_calibration.py --limit 20 \
  --output-dir /tmp/t86-deepseek --judges-only \
  --judge-providers deepseek --judge-modes binary
uv run python scripts/judge_calibration.py \
  --output-dir /tmp/t86-deepseek --labels /tmp/t86-deepseek/labels.json
```

Судья всегда оценивает полный текст ответа, а не только 8 утверждений из
пакета: иначе повторный `split_claims` склеивает соседние утверждения и
verdict'ы перестают соответствовать id. Для quote-режима добавьте
`--judge-modes quote`; на этом наборе он покрывает меньше утверждений.

Полный текст ответов и фрагментов книг пишется только в указанный каталог
(`/tmp` по умолчанию), в git не попадает.
