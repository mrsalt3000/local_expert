# Retry failed и диагностика ingestion (T93, 2026-11-04)

## Причина

- Qdrant на широких запросах отвечал 7–9 с, а клиент использовал дефолтный
  таймаут ~5 с → `ResponseHandlingException`, которую `indexer.py` маскировал
  под `qdrant is unavailable`.
- Книги с большим числом чанков отправлялись в Qdrant **одним upsert**;
  после исправления батчи режутся по **256** points.
- Embeddings уже резались byte-aware (8 MiB) из T89.

## Что изменено

- Клиент Qdrant: `timeout=30` вместо дефолта.
- `_qdrant_failure_message`: таймаут/HTTP-ошибка/connect различаются, в тексте
  остаётся исходная причина; `qdrant is unavailable` — только для `ConnectError`.
- Upsert батчами по 256 points.
- Новая команда `book-expert retry-failed [--dry-run] [--limit N] [--json]
  [--include-no-text]`: переиндексирует failed-книги, по умолчанию пропускает
  `no extractable text`, идемпотентна (`--force` внутри).
