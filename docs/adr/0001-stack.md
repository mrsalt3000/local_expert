# ADR-0001: Стек локального book-only RAG-эксперта

- Статус: accepted
- Дата: 2026-10-31
- Retrieval-часть уточнена в [ADR-0004](0004-drop-llamaindex.md)

## Контекст

Система должна работать локально (Ubuntu/WSL 2, RTX 3060 Laptop 6 GB, без
внешних сервисов по умолчанию), загружать книги, отвечать с цитатами и
работать как автономный coding-агент. Нужны: контролируемый ingestion,
гибридный поиск, tool-calling, MCP-доступ для других агентов и наблюдаемость.

Ограничения: приватный текст книги нельзя отправлять в облако или коммитить;
запуск должен быть воспроизводимым через `uv`; стек не должен требовать
Kubernetes/облака.

## Решение

- **Язык и окружение:** Python 3.12, `uv`, пакет `book_expert` в `src/`.
- **Агент:** LangGraph (react-цикл, state, лимиты шагов) + LangChain tools.
- **RAG:** собственный retrieval на Qdrant + SQLite FTS5 + RRF (см.
  ADR-0004); LlamaIndex не используется в v1. LangGraph отвечает за
  оркестрацию агента.
- **Vector DB:** Qdrant в Docker Compose. Одна коллекция `books`; изоляция книг
  через payload (`book_id`, `pdf_page_index`, `printed_page_label`,
  `section_path`, `chunk_id`). Отдельная коллекция на книгу отклонена: усложняет
  routing и fallback-поиск по всей библиотеке.
- **Лексический поиск:** SQLite FTS5 в локальном каталоге, фузия с dense через
  Reciprocal Rank Fusion (RRF) на стороне приложения. Причина: не нужен
  отдельный sparse-embedder (`fastembed`/ONNX), меньше моделей и загрузок,
  полный контроль над токенизацией; каталог SQLite уже существует.
  Ограничение: гибридный запрос не выполняется одним вызовом Qdrant;
  пересмотреть при росте библиотеки.
- **Модели:** Ollama по умолчанию (chat `qwen3.5:4b`, embeddings `bge-m3`).
  Провайдер абстрагирован; OpenAI-совместимый API включается через `.env`.
- **Parsing:** PyMuPDF как baseline native-text path. Docling — отдельный
  адаптер для layout/tables/OCR-экспериментов, не обязательная зависимость
  baseline.
- **Интерфейсы:** Typer CLI и MCP stdio server.
- **Наблюдаемость:** структурированные JSONL-трейсы (retrieval, router,
  tool-calls) и audit в `data/artifacts/`.

## Альтернативы

- **Свой минимальный tool-loop** — меньше зависимостей, но выбранный
  multi-agent/coding-сценарий требует state, checkpointing и готовых tools.
- **LlamaIndex agents на всё** — слабее в произвольных coding-tools и shell.
- **Chroma** — проще API, но слабее фильтрация и гарантии при росте.
- **Qdrant embedded** — не сервис, расходится с требованием отдельного
  локального сервиса и health-check.
- **Sparse-векторы в Qdrant** — нативный hybrid, но дополнительная модель и
  зависимость; отложено до появления реальной потребности.

## Последствия

- Плюсы: зрелые RAG-примитивы, явный агентный граф, локальные модели,
  предсказуемая изоляция книг, MCP-интеграция.
- Минусы: два фреймворка (LangGraph + LlamaIndex) увеличивают число
  зависимостей и требуют дисциплины, чтобы не дублировать слои; гибридная
  фузия реализуется самостоятельно; Qdrant требует Docker.
- Follow-up: измерить recall/latency на реальной библиотеке; при деградации
  рассмотреть sparse-векторы или reranker (ADR-0004+).
