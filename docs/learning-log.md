# Learning Log

Журнал обучения по проекту. Добавляйте записи в обратном хронологическом порядке.

## 2026-11-01
- Ollama runner по умолчанию поднимается с `num_ctx=4096`, даже если модель
  заявляет больше. Длинный ответ обрывается, когда `prompt + completion`
  достигает 4096; лечится явным `BOOK_EXPERT_OLLAMA_NUM_CTX` (8192) в
  `/api/chat`, а не только увеличением `num_predict`. Агентский `ChatOllama`
  получает тот же `num_ctx`.
- Веб-чат по умолчанию открывается в режиме «Супер»; существующие чаты
  сохраняют свой режим.
- FTS5 trigram не стоит внедрять: против `unicode61` с `or_prefix5` он не даёт
  различимого прироста, а индекс растёт примерно в 5 раз. Главная проблема
  лексики — AND-запрос: 48 из 52 кейсов давали 0 хитов. Добавлен opt-in
  `BOOK_EXPERT_LEXICAL_QUERY_MODE=or_prefix5`; default остаётся `and`, потому
  что на ручных 22 вопросах OR+prefix5 ухудшил chunk MRR@5.

## 2026-10-31
- `qwen3.5:4b` в Ollama по умолчанию тратит `num_predict` на thinking и отдаёт
  пустой `message.content`; провайдер теперь отправляет `think=false`
  (`BOOK_EXPERT_OLLAMA_THINK`), а пустой ответ трактуется как отказ.
- Гибридный поиск: Qdrant dense + SQLite FTS5 + RRF оказался достаточным для
  MVP; sparse-эмбеддер не нужен.
- Локальный Qdrant удобно тестировать через `QdrantClient(":memory:")`, но
  payload-индексы в этом режиме не действуют.
