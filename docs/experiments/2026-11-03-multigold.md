# Multi-gold оценка retrieval, 2026-11-03 (T83)

Гипотеза: single-gold разметка занижает retrieval, потому что верный ответ
может находиться в другом чанке той же страницы, в соседнем фрагменте раздела
или в почти дословном дубле издания, а метрика ставит за него `0`.

Основание — «Hands-On RAG for Production», стр. 193–196: golden chunks нужны,
но поддерживать их в динамике трудно; MAP устойчив, когда релевантных
фрагментов несколько; nDCG поддерживает graded relevance.

**Итог: гипотеза не подтвердилась.** Наивное правило «та же страница»
засчитывает посторонний текст и просто дублирует page recall; при требовании
текстового совпадения альтернатив в каталоге почти нет. Single-gold chunk
recall не занижен сколько-нибудь существенно, а разрыв chunk↔page —
определение метрики, а не потеря качества поиска.

## Условия

| Параметр | Значение |
| --- | --- |
| Наборы | `multi-book-40.local.json` (69 кейсов, 10 книг), `combined-120.local.json` (120 кейсов, 5 книг) |
| Embeddings / коллекция | `bge-m3` / `books` (прод-дефолты, не менялись) |
| `k` | 20 |
| Scope | `candidates`, лимит 24 книги |
| OR-канал | вес 0.1 (дефолт с T65) |
| Воспроизведение | `uv run python scripts/multigold_eval.py <dataset> --annotations-out ... --output ...` |

## Проверенные варианты разметки

Обе версии детерминированы и не зависят от retrieval.

**`structural-v1` — «та же страница / сосед по разделу / дубль».** Оценки:
gold 2; другой чанк той же страницы, сосед по `section_path` при
`|Δordinal| ≤ 1`, почти дословный дубль (Jaccard 3-грамм ≥ 0.6) — 1.
Покрытие: 69/69 и 111/120 кейсов, в среднем 3.74 и 3.47 допустимых чанка.

| Набор | chunk hit@5 single → multi | page recall@5 | Изменилось кейсов |
| --- | --- | --- | --- |
| 69 | .4348 → .7826 | .7826 без изменений | 24/69 в top-5 |
| 120 | .8000 → .8500 | .8500 без изменений | 6/120 в top-5 |

**Почему v1 отвергнута.** Multi-gold chunk hit совпал с page recall — это
следствие правила, а не независимое измерение. Проверка текстов на 24
изменившихся кейсах: Jaccard между gold и «допустимой» альтернативой
**0.00 во всех 24** (p25 = 0.00, median = 0.00, max = 0.09), расстояние по
ordinal — медиана 2. То есть засчитывались соседние абзацы страницы, не
содержащие ответ. Такая метрика просто пересчитывает page recall в терминах
чанков и не доказывает, что эталон был слишком строгим.

**`structural-v2` — альтернатива обязана быть текстово близка.** То же самое,
но сосед по странице/разделу засчитывается только при Jaccard 3-грамм ≥ 0.3
с gold; межкнижный дубль — при ≥ 0.6. Покрытие: **3/69** кейсов (только
`duplicate_text`), **0/120**.

| Набор | chunk hit@5 single → multi | chunk hit@k single → multi | page recall |
| --- | --- | --- | --- |
| 69 | .4348 → .4348 | .5652 → **.5797** | .7826 / .8696 без изменений |
| 120 | .8000 → .8000 | .8833 → .8833 | .8500 / .9083 без изменений |

Изменился **один** кейс из 69 (дубль попал в top-20) и **ноль** из 120.
Page MAP@k/nDCG@k: 69 — .7305/.7632; 120 — .7325/.7747.

## Что это значит

1. **Single-gold chunk recall не занижен.** При честном правиле
   (текстовое совпадение) альтернатив почти нет: 3 фрагмента на 69 кейсов и
   ни одного на 120. Дельта hit@k — +1 кейс.
2. **«Та же страница» — не признак допустимости.** 24/24 проверенных
   альтернативы текстовно не связаны с gold. Пользователь видит страницу
   целиком, поэтому page recall — правильная метрика; chunk-level
   допустимость требует совпадения содержания, а не соседства.
3. **Разрыв chunk/page — определение.** `.4348` против `.7826` (69) и `.6576`
   против `.85` (120) означает «найден точный фрагмент» против «найдена
   страница», а не «поиск потерял контент». Для решений о retrieval брать
   page recall / hit по странице.
4. **Похожих изданий в каталоге практически нет.** Две группы одинаковых
   названий («Вступление» ×3, «untitled» ×2) с eval не пересекаются; почти
   дословных межкнижных дублей — 3 на 69 кейсов. Предварительная оценка
   «6 групп / 14 пар Jaccard ≥ 0.8» не подтвердилась нормальным аудитом.

## Решение

Dual reporting, дефолты не меняются, но рекомендуется **v2-разметка**:

- single-gold остаётся дефолтом `stage-eval`/`agent-eval`;
- `--multigold <file>` добавляет `retrieval_multigold` (hit/recall/MAP/nDCG по
  чанкам и страницам) и `multigold` в каждой строке `details`;
- `agent-eval --multigold` добавляет precision/hit по допустимым страницам,
  single-gold `citation_precision` не переопределяется;
- `scripts/multigold_eval.py` по умолчанию строит v2 (`--neighbour-min-jaccard
  0.3`), v1 воспроизводится через `0.0`;
- прод-код поиска не менялся.

## Ограничения

- Текстовый порог 0.3 — эвристика: пересказ другими словами не попадёт в
  допустимые, поэтому v2 — консервативная нижняя граница.
- Разметка детерминирована, но не вычитана человеком; проверка 24 кейсов
  сделана по Jaccard и ordinal, без смысловой экспертизы.
- Поиск дублей по тексту опирается на лемма-FTS и не находит пересказ.
- Прогоны на `bge-m3`; после переключения на qwen3 числа надо пересчитать
  (разметка от модели не зависит).
