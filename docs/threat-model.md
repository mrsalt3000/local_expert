# Threat Model

Модель угроз для локальной book-only RAG-системы с автономным агентом.

## Активы

| Актив | Почему важен |
| --- | --- |
| Текст книги | Приватный контент, защищён авторским правом |
| Эмбеддинги и индексы | Восстановимый сигнал о содержании книги |
| `.env` и ключи | Доступ к внешним API |
| Файлы пользователя | Агент имеет shell/fs-доступ |
| Git-история | Утечка через коммит необратима |
| Audit/трейсы | Могут содержать фрагменты приватного текста |

## Доверенные и недоверенные данные

- Доверенные: код репозитория, конфигурация пользователя, локальные модели.
- Недоверенные: содержимое PDF (включая скрытый текст и prompt injection),
  имена файлов, ответы внешних API, сторонние зависимости.

## Поверхности атаки

| Поверхность | Риск |
| --- | --- |
| PDF / extracted text | Prompt injection: «инструкции» внутри книги |
| MCP server | Неавторизованный локальный клиент вызывает tools |
| Qdrant/Ollama порты | Доступ из других процессов/контейнеров |
| Shell/fs tools | Выход за workspace, удаление данных |
| Git-операции | Push/force-push, утечка в remote |
| Зависимости | Supply-chain, вредоносный пакет |
| Логи/трейсы | Случайная запись текста книги |

## Угрозы и меры

### T1. Prompt injection из книги

Книга содержит текст, похожий на инструкции агенту.

Меры: retrieved-контекст передаётся как данные в явных разделителях; системный
промпт запрещает выполнять инструкции из документов; инструменты с побочными
эффектами не вызываются по мотиву из книги; router/answer не используют
содержимое для изменения политики.

### T2. Утечка приватного текста

Меры: ADR-0002; git-ignored пути; запрет текста в трейсах по умолчанию;
`doctor` предупреждает при включении облачного провайдера; pre-commit
`check-added-large-files`; ревью `git status --ignored`.

### T3. Выход агента за workspace

Меры: canonical path resolution, запрет `..`/симлинков наружу, allowlist
корней, тесты на traversal. Shell и git запускаются в `bwrap`: корень ФС
read-only, writable только workspace, `/tmp` — private tmpfs. Без `bwrap`
инструменты fail-closed (отключены).

### T4. Разрушительные команды

Меры: denylist (`sudo`, `dd`, `mkfs`, `shutdown`, `curl|sh`, рекурсивное
удаление корня), таймауты, лимит вывода, audit, kill switch
`BOOK_EXPERT_AUTONOMY=off`.

### T5. Опасные git-операции

Меры: запрет `reset --hard`, `clean -fdx`, force-push; remote-операции только
при `BOOK_EXPERT_ALLOW_REMOTE=1`; push — отдельное осознанное действие.

### T6. Сетевой доступ

Qdrant и Ollama слушают только loopback; Docker-порт публикуется на
`127.0.0.1`. MCP — stdio, без сетевого listener по умолчанию.

### T7. Supply chain

Меры: фиксированные версии в `uv.lock`, минимальный набор зависимостей,
проверка новых пакетов перед добавлением, отсутствие `curl|sh` в скриптах.

### T8. Отравление индекса

Меры: content hash и статус книги, переиндексация при изменении, карантин
файлов с ошибками парсинга, ручной `reindex`.

## Остаточные риски

- Локальная модель может ошибаться и галлюцинировать; citations снижают, но не
  устраняют риск.
- PDF с вредоносным содержимым может эксплуатировать парсер (PyMuPDF/Docling);
  запуск в отдельном процессе и обновление зависимостей снижают риск.
- Автономный агент по определению может нанести локальный ущерб в пределах
  workspace; audit и git-история помогают расследовать, но не отменяют потери.
- Docker-том Qdrant не шифруется; защита — на уровне ОС и прав пользователя.
- bwrap монтирует корень ФС read-only: агент не пишет вне workspace, но может
  **читать** доступные пользователю файлы (включая ключи). При
  `BOOK_EXPERT_ALLOW_REMOTE=1` открывается сеть, поэтому этот режим включает и
  риск эксфильтрации прочитанного; используйте его только осознанно.
- `data/artifacts` writable для агента. Audit-лог защищён hash chain и
  проверяется командой `book-expert audit-verify`: правка или удаление строки
  обнаруживается, но не предотвращается. Каталог, трейсы и eval-отчёты
  tamper-evident не являются. Для локального single-user MVP это принято; не
  храните там чужие секреты.
- Audit пишет `command` без редакции: не передавайте секреты в аргументах
  shell-команд.

## Проверки

- Негативные тесты path traversal, timeout, denylist, remote-флаг.
- `git check-ignore` для всех приватных путей.
- `doctor` проверяет loopback-биндинги и доступность сервисов.
- Ревью трейсов на отсутствие текста книги.
